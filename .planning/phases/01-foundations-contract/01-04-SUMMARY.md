# Phase 1 Plan 04: Nocturne Tokens, Theme and Fonts Summary

**`tools/gen_tokens.py` (stdlib) turns `design-system/nocturne.tokens.json` into a committed `NocturneTokens.kt` + `nocturne_colors.xml` guarded by `--check`. `NocturneTheme` maps them onto Material 3 and `LocalNocturne`. Ten static subset OFL fonts give glyph-level Devanagari fallback through `Typeface.CustomFallbackBuilder`. On the Redmi the showcase runs edge-to-edge on #0B0820 and shows every colour role, the 5 palm colours, and all 11 type styles, each with a Hindi line.**

- Duration: about 14 min (2026-11-26T10:58:28Z to 11:12Z)

- Files: 26 created or modified (22 created, 4 modified)

## Accomplishments

- **Generator.** It walks the DTCG tree. Tokens can sit at depth 2 or 3, and `$type` can come from a parent group. It resolves `{refs}` and detects cycles, then emits the interface objects in token-file order. Semantic tokens become references (`val Primary = NocturneColors.BrandPrimary`), with no repeated hex. `#RRGGBBAA` turns into ARGB (`#6A4CF573` becomes `Color(0x736A4CF5)`). px becomes dp (negative values as `(-8).dp`), ms becomes `const val` Int, and cubicBezier becomes `CubicBezierEasing`. Gradients are emitted as stop arrays only. On a collision it exits 1 and names both token paths; it does the same for an unresolvable ref, a missing or empty `$value`, or an unknown `$type`. Two runs give identical output.
- **Theme.** `darkColorScheme` comes from `NocturneSemantic` per Pattern 4, and M3 `Shapes` from `NocturneRadius`. `NocturneExtras` holds palm, status and background colours, focus ring, ad outline, gradients, glows, durations, easings, `reduceMotion` (ANIMATOR_DURATION_SCALE, default 1f) and `type`. `windowBackground = @color/nocturne_bg_base`, so there is no cold-start flash. NocturneTheme.kt and ShowcaseScreen.kt contain no colour literals.
- **Fonts.** `tools/fonts.sh` downloads from google/fonts `6ebe737e44fd64ee736bbc6feed6136a6dbfd222` into a new empty work dir outside the repo (`scratchpad/fonts-work/src`). It instances the fonts (Noto at wdth=100) and subsets them with `--layout-features='*' --name-IDs='*'`. Output: 10 TTFs (1.6 MB total; Cormorant alone is 403 KB) and 4 OFL texts in `assets/licenses`, which are confirmed to be inside the APK. `--verify` checks that there is no fvar, the Latin and Devanagari coverage, GSUB, and the OFL text.
- **Fallback.** On API 29+ each (role, weight) gets one cached Typeface: Manrope falls back to Noto Sans Devanagari, and Cormorant to Noto Serif Devanagari, then the system serif or sans-serif. On API 26-28 a resource `FontFamily` is used. All 11 TextStyles use `FontSynthesis.None`. `devanagariSafe()` is applied to every style when the locale is `hi`, and to the showcase Hindi lines.
- **On the phone (Redmi, API 30).** The Display styles use serif Devanagari and the UI styles sans. हृ, ज्ञ and क्ष shape correctly, and nothing is clipped. Screenshots: `tools/adb/shots/showcase-type.png`, `showcase-colours.png`, `showcase-palm.png` (git-ignored, local).
- **Tools.** `screen.py` reads raw screencap (12/16-byte header picked from the byte count) for `pixel` and `hash`, with `--self-test`. `smoke-phone.sh SMOKE_SCROLLS=<n>` swipes about 2/3 of the screen height n times and matches the union of the dumps, then scrolls back up before a retry.

## Deviations from Plan

**1. [Rule 3 - Blocking] fontTools runs as `uv run ... python -I -m` instead of `uvx`**
- Found during: Task 2
- Issue: the environment rules require any Python that reads downloaded files to run with `-I`, and the `uvx` console-script entry points do not.
- Fix: `uv run -q --no-project --python 3.13 --with fonttools==4.68.0 python -I -m fontTools.varLib.instancer|fontTools.subset`, run from `tools/`. The pin and the tool are the same; only the launcher changed.
- Files: tools/fonts.sh. Commit: f54957d

**2. [Rule 2 - Missing critical] Generated `NocturneColors.ByPath` and `NocturneTypeSpecs.ByName`**
- Found during: Task 1 and Task 2
- Issue: the showcase must show every colour and every style labelled by token path or name, and a hand-written list would drift from the tokens.
- Fix: the generator emits ordered maps. `ByPath` and `ByName` are reserved identifiers, and a token that would map to either fails. Covered by the unit tests.
- Files: tools/gen_tokens.py, tools/test_gen_tokens.py, NocturneTokens.kt. Commits: 92a0798, f54957d

**3. [Rule 1 - Bug] Swatch labels wrapped after the type mapping landed**
- Found during: Task 2 on-device check
- Issue: `labelSmall` became Overline (Manrope Bold, 0.12em tracking). That wrapped the 5-wide palm row and split "palm.heart".
- Fix: the labels now use `bodySmall` (Caption), and both grids are 3 per row.
- Files: ShowcaseScreen.kt. Commit: f54957d

**4. [Rule 2] `onSurface = NocturneSemantic.Foreground` in the dark scheme**
- Pattern 4 does not list it. Because surface equals background, Surface content colour has to be the token foreground, not the M3 default grey.

**Total deviations:** 4 auto-fixed (1 blocking, 2 missing-critical, 1 bug). **Impact:** none on scope. Each one tightens the "no hand-copied values" and untrusted-download rules.
