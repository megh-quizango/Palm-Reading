## Phase Goal

ROADMAP Phase 2 goal (verbatim): A local backend turns a palm photo, hand side and hand landmarks into a validated, safe, cached Palm / Love / Career reading through an async job API, proven on real palm photos before any client wiring.

Note (MVP mode): the Goal line is not in user-story format and no story was invented. Run `/gsd-mvp-phase 2` if a user-story framing is wanted.

Note (tracer-first): this plan is the phase tracer. The job API spine (HTTP, job runner, image prep, Claude wrapper, assembly into the frozen contract) is wired end to end first with Claude mocked at the SDK boundary (D-16). The pure modules the research listed for wave 1 (line geometry, safety, cache) follow as expansion plans 02-02, 02-04 and 02-05, each wired into this spine and tested through it. Only plan 02-08 calls the real Claude API.

<objective>
A developer can POST a palm photo + hand side + locale + landmarks and poll a reading that validates against the frozen PalmReading v1 contract, with the real SDK call shape exercised against a fake Anthropic client (READ-02 happy path, D-01, D-03, D-04, D-05, D-07). Uploads never touch disk and lose their EXIF (READ-05, D-08). The prompt carries the never-list (READ-07 prompt half, D-13).

Purpose: prove the architecture (FastAPI job API -> asyncio runner -> Claude structured output -> strict contract) before any expansion builds on it.
Output: job API, job runner, image prep, LLM schema, versioned prompt, Claude wrapper, assembler, shared test fixtures.
</objective>
