## Phase Goal

ROADMAP Phase 2 goal (verbatim): A local backend turns a palm photo, hand side and hand landmarks into a validated, safe, cached Palm / Love / Career reading through an async job API, proven on real palm photos before any client wiring.

Note (MVP mode): the Goal line is not in user-story format and no story was invented.

<objective>
No returned reading ever contains a death, illness, pregnancy, medical, legal or financial directive (READ-07). The prompt never-list shipped in 02-01; this plan adds the server output filter with field rewrite and the text red-team gate (D-13).

Purpose: defence in depth for an entertainment app sold in India, SE Asia and LatAm; the prompt alone is not enough, and a filtered field is rewritten rather than failing the job.
Output: safety.py, reader wiring, red-team tests.
</objective>

Implements the D-13 rewrite path for one English topic rule end to end; Task 2 completes the rule tables.

1. safety.py: `normalise(s)` = `unicodedata.normalize("NFKC", s).casefold()`, then drop every character whose `unicodedata.category` is "Cf" (zero-width space, joiners, soft hyphen), then delete U+093C (nukta) and map U+0901 (chandrabindu) to U+0902 (anusvara). It is applied to the match copy only (never to the returned text), and every Devanagari stem is passed through normalise too, so stems and text fold the same way. A rule table of compiled regexes with ids; start with the English death and lifespan family (`\bdie\b(?!-hard)`, dying, death, early death, lifespan, life expectancy, with word boundaries) and the length-of-life rule `\b(long|short) life\b(?![\s-]*lines?\b)`, which hits "a long life ahead" and "you will have a long life" but skips "a long life line" and "short life-line" (the p1 prompt asks the model to describe each line's length). `hits(text)` returns the ids of matching rules. `NEUTRAL["en"]` holds one calm, generic entertainment sentence per string field (summary, how_you_love, ideal_partner, love_challenges, strengths, career_challenges, interpretation) and a default 3-item list for traits and ideal_industries. `filter_llm` returns a model_copy of the LlmReading with each hit string field replaced by its NEUTRAL text, plus the number of rewritten fields.
2. palm_reader.read: run `filter_llm(reply.parsed, locale)` before `assemble`; store the count in a new defaulted field `ReadResult.safety_hits`; keep `ReadResult.llm` as the unfiltered model output (enum agreement in the eval) and never put it in a job or cache.
3. test_palm_reader.py `test_death_prediction_is_rewritten`: FakeSdk with ok_reply whose how_you_love says the life line shows an early death -> reading.love.how_you_love equals `NEUTRAL["en"]["how_you_love"]`, `safety_hits == 1`, the reading validates, the other fields are unchanged.
